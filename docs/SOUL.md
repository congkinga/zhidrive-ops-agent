# Product Soul

- One-line description / 一句话介绍：`面向高阶智能驾驶产品运营的 AI 辅助场景评测、问题分类、归因复盘和公开行业情报研究工具。`
- Product form / 产品形态：`想法 + 可运行静态 Demo`
- Stage / 阶段：`0→1`

## Users and situations / 用户与场景

- Current users / 当前用户：`暂无真实用户`
- Candidate users / 候选用户：`智能驾驶产品运营、体验评测、质量闭环、产品经理和跨部门协同角色`
- Situations of need / 需求场景：`需要统一 NOA 场景评测口径；需要把用户反馈和实测 case 分类定级；需要沉淀问题跟进闭环和竞品观察`
- Core job to be done / 核心任务：`假设：把一个智驾体验问题从场景、现象和证据转成可派发、可验证、可复盘的标准化问题记录`

## Value / 产品价值

- Problem solved / 解决的问题：`暂定：智驾体验反馈分散，缺少统一场景标签、问题维度和闭环模板`
- Core value proposition / 核心价值主张：`假设：用场景化评测表和五维问题分类，把主观体验问题转成可推进的产品优化任务`
- Differentiation / 差异化：`暂定：同时连接公开行业趋势、场景评测、问题归因和闭环模板`
- Desired business outcome / 当前业务目标：`用一个可展示的 0→1 项目验证产品运营能力，并沉淀可复用方法论`

## Product reality / 产品现状

- Available capabilities / 已有能力：`静态 Demo 支持场景录入、问题五维分类、严重度标记、证据链接、责任方建议和闭环模板`
- Website and channels / 官网与渠道：`无线上官网；当前使用本仓库的本地静态页面作为 Demo`

- Constraints / 品牌、法律、预算与平台约束：`不得使用企业内部数据；不得公开具体车型缺陷的未确认事实；公开行业信息必须附来源；不伪造测试结果`

## Evidence and hypotheses / 证据与假设

- Verified facts / 已验证事实：
  - 当前产品载体是静态 Demo，来源：`product/landing/zhijia-nova-ops.html`
  - 产品交互路径为“录入场景与现象 → 输出五维问题分类和闭环建议”，来源：`product/README.md`
  - 公开报道显示，部分调研称城市 NOA 经常使用比例不高，高速场景激活占比较高，来源见 `memory/run-seo-page-loop/2026-08-17-observation-seo-zhijia.md`
- Active hypotheses / 当前假设：
  - 智驾产品运营最需要的是场景化评测标准，而不是更多竞品参数
  - 问题分类、严重度和责任方建议可以明显降低跨团队沟通成本
  - 公开行业内容适合面向产品运营从业者做 SEO，不适合直接照搬小红书消费品内容
- Open questions / 待回答问题：
  - 产品 Demo 是否应接入真实车端日志或用户反馈导出
  - 五维问题分类是否需要增加法规合规、OTA、责任边界等维度
  - 哪些公开行业指标可以稳定追踪并形成周报
